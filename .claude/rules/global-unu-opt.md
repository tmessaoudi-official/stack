# /opt tool installer (templates/shell/global-unu-opt.sh)

Split out of `CLAUDE.md` by `/rules-split` on 2026-10-09: the text below is unchanged except for cross-references and line citations, and each entry keeps a one-line index entry in `CLAUDE.md`. A new lesson about these files belongs HERE, not in `CLAUDE.md`.

## templates/shell/global-unu-opt.sh (from CLAUDE.md § Key Scripts)

Installs the `.env` pin of the tools under `/opt/$USER` — IntelliJ IDEA, PhpStorm, WebStorm, Android Studio, VS Code, Devin, Sublime Text, MeGit, balenaEtcher, task, bat, sonar-scanner-cli — and owns the desktop launchers of the GUI ones (`docs/plans/opt-developer-updater.plan.md`). `--check` (default) reads installed versions offline and writes nothing; `--apply` downloads the pin into `<root>/.gs-staging/`, checks its sha256 (Sublime and bat publish none: logged `NOCHECKSUM`; MeGit's is the GitHub asset digest, fetched from api.github.com with `GLOBAL_STACK_GITHUB_TOKEN` when `.env.local` sets it — piped to curl on stdin, never in argv — else anonymously), reads the extracted version without running unverified bytes, and swaps; `--only=<id>[,…]`. `global-unu.sh` runs it last with `--apply` (the `# >>> gs-unu-opt` block) from its own directory, so **both scripts must be deployed together** — the `~/.local/bin` copies are hand-copied, and `make hard-restart` runs that copy (`yes y | global-unu.sh`), so once deployed a hard restart also installs every /opt tool whose pin moved (GBs for an IDE). Pins are proposed by `env-update` like any other; a JetBrains major is the YEAR, Android Studio's pin is its build id (`AI-…`), every Sublime build HOLDs, and Devin's feed serves only its latest build. **The three Electron apps — VS Code, Devin and balenaEtcher — need cached sudo** (2026-09-29): Electron aborts at startup unless `<tree>/chrome-sandbox` is root-owned 4755 (`FATAL:setuid_sandbox_host.cc … not configured correctly`), and a plain install leaves it `developer:developer 755` — a Devin upgrade did exactly that and Devin would not start until `/etc/profile.d/stack.sh` ran again at the next login. The engine now runs `sudo -n chown root:root` + `chmod 4755` on the STAGED tree before the swap (chown first: it clears setuid), and on `--apply` also repairs a tool that is already `current` with a wrong sandbox (an install never re-enters that path); `--check` prints a `[sandbox]` line for one, write-free and sudo-free, saying whether `--apply` will repair it or refuse. **The repair setuids only the bytes a verified install recorded** (audit 2026-10-06 F3: `/opt/$USER` is 777 with no sticky bit, so the repair used to make whatever sat at `<tree>/chrome-sandbox` setuid root): an install records the sha256 of the STAGED sandbox — bytes from the checksummed archive, taken before the swap — in `${XDG_STATE_HOME:-~/.local/state}/global-unu-opt/<id>.chrome-sandbox.sha256` (seam `GS_UNU_OPT_STATE_DIR`), outside the 777 tree, written only after the swap succeeds. A sandbox whose bytes differ, or one with no record, is `REFUSED` before any sudo call, and the message names the route — `mv '<tree>' '<tree>.untrusted' && global-unu-opt.sh --apply --only=<id>`, because there is no reinstall verb. Trees installed before 2026-10-06 have no record, so their first repair refuses until they are reinstalled once (UNCERTIFIED-BY-EXECUTION on the real `/opt`: stubbed in §15). Residual, not closed: a path swap between the digest check and `sudo chown` (a race inside one run) is still possible; closing it needs fd-based checks. With no cached credentials an install FAILS (old copy untouched) and says to run `sudo -v`; a repair FAILS with the exact `sudo chown … && sudo chmod …` to run. When stdin is a tty and sudo has expired the engine asks once (`sudo -v`) and retries; it never prompts without a tty, so `yes y | global-unu.sh` cannot block on a password. The IDEs are deliberately outside that set — their jcef helper ships a `chrome-sandbox` too, but the IDE is a JVM app (UNVERIFIED: no IDE has been launched since the engine installed 2026.2.3). `templates/shell/profile.sh` no longer touches the sandbox: its six login-time `sudo chown/chmod` lines did the same unchecked setuid at every login and were removed 2026-10-06 (`profile-shell.test.sh` 1b keeps them out). A deployed `/etc/profile.d/stack.sh` keeps them until the developer redeploys it. The firewall denies Claude's writes under `/opt`, so a real `--apply` there is the developer's to run.

## From CLAUDE.md § Testing & Verification

- **/opt tool installer tests**: `bash bin/tests/global-unu-opt.test.sh` — 119 checks, ~7 s, no network. `templates/shell/global-unu-opt.sh` installs the `.env` pin of the tools under `/opt/$USER` and owns their launchers (`docs/plans/opt-developer-updater.plan.md`). Runs in a temp tree through the script's `GS_UNU_OPT_*` seams with a stub `curl` that exits 22 under `-f` on any unregistered URL, as real curl does. Pins: `--check` writes and fetches nothing; a checksum, 404, wrong-version-inside or absent-pin failure leaves the installed tree byte-identical; a tool whose binary runs (`<proc>/*/exe`, not `pgrep -f`) is skipped — checked again just before the swap, since the app can be started during a multi-GB download; a failed move of the old tree never nests the new one inside it (`_opt_install` runs left of `||`, where `set -e` is inert, so every step is checked explicitly — two independent guards, each sufficient, sabotaged together); a tree a failed run parked at `.gs-staging/<id>/old` stops the next install instead of being wiped with the staging dir; `rm -rf` only strictly inside `.gs-staging/` — every probed path is disposable, never `/`; a launcher is written only after `desktop-file-validate` accepts it and only when its content changed. §10 installs each shipped row (PhpStorm, WebStorm, Android Studio — whose pin is the BUILD id `AI-…`, the only version its tree carries) on a fresh machine and reads it back offline; the JetBrains product codes are the test's own, never read from the script. §11 does the same for VS Code (versions API + sha256), Devin (its feed serves ONLY the latest build: a pin it no longer serves must fail naming the pin and download nothing) and Sublime (no published checksum: logged `NOCHECKSUM`, and the version is read from `changelog.txt` — the staged binary must never execute). §12 covers the three CLI tools moved out of `global-unu.sh` (task: a FLAT archive checked against `task_checksums.txt`; bat: no published checksum, version from `CHANGELOG.md`, never executed; sonar-scanner-cli: zip + `.sha256`, aarch64 too) and the arch gate (a row with no archive for `uname -m` is `unsupported`, never fed an x86_64 one); §13 runs the SHIPPED `# >>> gs-unu-opt` block of `global-unu.sh` against a stub sibling: `--apply`, a failure or a missing sibling fails `global-unu.sh`, and it is the last step before `Successful :)`. Twenty-four sabotages each red their check. §14 (step 5) covers MeGit — the asset digest, the token sent as a header on stdin and never in curl's argv (a stub logs both), anonymous without it, a digest mismatch leaving the old tree byte-identical, aarch64 — and Etcher — `SHA256SUMS.Linux.x64.txt`, the version read from a REAL asar header (never executed), `sudo -n` making the STAGED `chrome-sandbox` root 4755 before the swap (a stub `sudo`), no cached sudo failing with the old tree byte-identical, and a zip failing its sha256 never reaching `sudo` (so setuid only ever lands on a checksummed sandbox — a sabotage running `prepare` before the check reds it). The stub `sudo`'s chown clears setuid as chown(2) does, so a `chmod 4755` placed before the chown reds 14i; ten more sabotages each red their check. §15 (2026-09-29) covers the Electron sandbox for VS Code, Devin and Etcher: the staged sandbox made root 4755 before the swap (a stub `sudo` whose chown clears setuid, so chmod-before-chown reds), FAILED without sudo with the installed tree byte-identical, a bad sha256 never reaching sudo, an archive without a sandbox refused, a `current` tool repaired on `--apply` (mode AND owner — `developer:developer 4755` still counts as wrong), a correct sandbox costing zero sudo calls, `--check` reporting without writing, IDEA (which ships one at its root in the fixture) never reaching sudo, and the tty path — `sudo -v` once, then `sudo -n` — under `script(1)`. `_run` closes stdin so a suite run from a terminal cannot reach the interactive branch, and `GS_UNU_OPT_SANDBOX_OWNER` (default `root`) is the seam that lets a non-root fixture count as correct. Ten mutations each red their own check (one of them — IDEA added to the set — first stayed GREEN: the fixture kept its sandbox where the repair never looks, the check that cannot fire; 15m now plants a wrong one at the tree root and that mutation reds it).
